# ฉบับผู้เรียน M6.10 — SOC Automation ด้วย Claude + MCP

โฟลเดอร์นี้คือไฟล์ lab **ฉบับไม่มีเฉลย** โครงเดียวกับไฟล์ของผู้สอนทุกส่วน ยกเว้นส่วน "เฉลย" ถูกแทนด้วย "บันทึกคำตอบ" ให้กรอกเอง ผู้สอนถือฉบับเต็มใน [โฟลเดอร์แม่](../README.md) ศัพท์ที่ไม่คุ้นดูใน [glossary](../../../docs/glossary.md)

## วิธีใช้ทีละ lab

1. **อ่าน "โจทย์"** ให้รู้ว่า lab นี้ปิด gap อะไร และตรงกับหัวข้อใดของ Module 5–6
2. **อ่าน "สิ่งที่ต้องค้นให้ได้"** ก่อนพิมพ์ prompt — นี่คือรายการคำถามที่ต้องตอบให้ครบ แต่ละข้อบอกด้วยว่าหลักฐานต้องมาจาก tool ใด
3. **พิมพ์ prompt** ตามส่วน "prompt ที่ผู้เรียนพิมพ์" ใน Claude Desktop ที่ต่อ MCP ทั้งสองตัว เปลี่ยน `<ชื่อ>` เป็นชื่อตัวเองทุกครั้ง (namespace `/m6-10/<ชื่อ>/`) เพราะ Spark เขียนแบบ `errorifexists` ทับของคนอื่นไม่ได้
4. **ดู tool ที่ Claude เรียก** เทียบกับ "ลำดับ tool ที่ควรเห็น" ถ้า Claude ตอบโดยไม่เรียก tool หรือข้ามขั้น ให้สั่งใหม่ และจดลงส่วน "Claude ผิดตรงไหนได้บ้าง" ว่าเกิดข้อใดจริง
5. **กรอก "บันทึกคำตอบ"** ทุกข้อตามเลขในตาราง "สิ่งที่ต้องค้นให้ได้" คอลัมน์ขวาต้องระบุ tool และฟิลด์หรือบรรทัดที่อ่านค่ามา เช่น `hdfs_query_records → sum_fields.orig_bytes`
6. **ทำ "จุดที่คนต้องทำ"** — ข้อเหล่านี้ Claude ทำแทนไม่ได้ (อนุมัติ, ตรวจ sha256, ตัดสินใจ confirm/dismiss, นิยาม baseline) เขียนคำตัดสินและเหตุผลลงท้าย "บันทึกคำตอบ"
7. **ส่งไฟล์ lab ที่กรอกแล้ว** (markdown ทั้งไฟล์) ให้ผู้สอนตรวจกับฉบับเฉลย

## กติกาการตอบ

- ตัวเลขทุกตัวต้องมาจากผลของ tool ไม่รับตัวเลขที่ Claude "ประเมิน" หรือสรุปเองโดยไม่มี tool รองรับ
- ไม่เชื่อผล Spark job จนกว่า `spark_job_status` คืน `SUCCEEDED` และ report ต้องผ่าน `log_skill_validate_report`
- ข้อที่เป็นการตัดสินใจ (นิยาม "ปกติ", threshold, confirm/dismiss) ไม่มีคำตอบตายตัว แต่ต้องอ้างตัวเลขที่ค้นได้
- เมื่อ Claude สรุปว่า "ถูกโจมตี" ให้ย้อนดูว่า tool คืน `interpretation: no incident verdict` หรือไม่ แล้วแก้คำสรุปให้ตรงกับหลักฐาน
