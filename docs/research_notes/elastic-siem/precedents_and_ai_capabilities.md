## Key Question 1: Open-source SIEM distributions built on Elastic or OpenSearch, and compose/starter repos — what each ships, license, status, and classroom-lab fit

### Takeaway
There is no maintained, widely-adopted "Elastic SIEM in a compose file" distribution; the closest reusable precedents are **deviantony/docker-elk** (18.4k stars, MIT, Elastic 9.5.5, Fleet via extension/tls branch but no SIEM content) and **peasead/elastic-container** (577 stars, Apache-2.0, "Elasticsearch, Kibana, Fleet, and the Detection Engine all pre-configured", last push Apr 2026, pinned to 9.0.1). The big "SIEM distributions" either run on **OpenSearch forks** (Wazuh, Clear NDR Community ex-SELKS) — so they do not contain Elastic Security's detection engine, Fleet integrations or Elastic Defend — or are unsuitable for a one-laptop macOS lab (Security Onion: x86-64 only, 24 GB standalone minimum, ELv2; HELK: ES 7.6.2, alpha, no commits since mid-2024; SOF-ELK: a SANS VM appliance).

#### Why OpenSearch vs Elastic matters
- OpenSearch was forked from Elasticsearch 7.10.2 under Apache 2.0 after removing X-Pack code; OpenSearch rebuilt equivalents (Security plugin, ISM, Alerting, Anomaly Detection) as Apache-2.0 plugins; its SIEM counterpart is the Security Analytics plugin — [Quesma blog](https://quesma.com/blog/opensearch-vs-elasticsearch-a-fork-in-the-road/); [OneUptime 2026-01](https://oneuptime.com/blog/post/2026-01-21-elasticsearch-vs-opensearch/markdown) (secondary sources)
- OpenSearch Security Analytics: "a security information and event management (SIEM) solution for OpenSearch"; detectors mapped to MITRE ATT&CK; "Detection rules use open source Sigma rules as a starting point"; a correlation engine that can "compare findings from different log types and draw correlations between them"; out-of-the-box log types incl. Windows, Linux, CloudTrail, DNS, Okta, VPC Flow — [OpenSearch docs](https://docs.opensearch.org/latest/security-analytics/)
- Elastic Security (detection engine, prebuilt rules, Fleet integrations, Elastic Defend) is Kibana x-pack / ELv2 code and is therefore absent from OpenSearch-based stacks (Wazuh, Clear NDR) — [kibana LICENSE](https://raw.githubusercontent.com/elastic/kibana/HEAD/LICENSE.txt); [elastic-agent LICENSE](https://raw.githubusercontent.com/elastic/elastic-agent/HEAD/LICENSE.txt) (inferred linkage)

### Inferences
- Fit verdicts for a one-laptop macOS Docker Desktop classroom lab (my judgement from the cited facts):
  - **peasead/elastic-container — best direct precedent to imitate** (Fleet Server + Detection Engine + TLS + prebuilt rules enabled by script; Apache-2.0; macOS listed). Weaknesses: single bash script rather than declarative files, pinned 9.0.1, last push Apr 2026.
  - **deviantony/docker-elk — best maintained compose skeleton** (9.5.5, MIT, `tls` branch + `fleet` extension), but contains zero SIEM content; an agent would have to add detection-rule install, dashboards and pipelines.
  - **elastdocker — good alternative skeleton** (Basic license by default, parameterised heap) but no Fleet; **start-local — fastest demo** but no TLS/Fleet and explicitly "local testing only".
  - **Wazuh — runs well in Docker including ARM Linux hosts, but teaches Wazuh/OpenSearch, not Elastic Security**; GPL-2/AGPL-3 content cannot be mixed into an ELv2 Elastic Security build without care.
  - **Security Onion — not viable** on Apple Silicon (x86-64 only, 24 GB standalone, ISO/VM install, ELv2 acceptance).
  - **HELK — not viable** (ES 7.6.2, alpha, Linux-only installer, no commits since 2024). **SOF-ELK — VM-only** and its maintainers say files are not meant to run outside the VM; its Logstash parsers/dashboards are the reusable part (GPL-3). **Clear NDR — OpenSearch NDR**, out of scope.
  - **elastic/detection-rules + elastic/integrations are the real "content" precedents**; both ELv2, which permits use with the default distribution but is not OSI open source.
- The archived state of elastic/stack-docker, elastic/helm-charts, elastic/ansible-elasticsearch and elastic/examples means Elastic's official reference for "stack from files" is now start-local (local only), the Docker docs, ECK (Kubernetes) and the Terraform provider — not a compose repo.

## Key Question 2: Infrastructure-as-code for Elastic (Terraform provider, Ansible, detection_rules CLI, saved-object import, config-as-code guidance)

### Takeaway
The **elastic/terraform-provider-elasticstack** (Apache-2.0, pushed 2026-11-02) now covers essentially the whole SIEM-as-code surface — index/component templates, ILM, ingest and Logstash pipelines, Fleet agent policies/integrations/outputs/server hosts, Kibana alerting rules, dashboards, saved-object import, prebuilt-rule installation, and `kibana_security_detection_rule` with exception lists — while Elastic's official Ansible roles are archived; the **detection-rules CLI** (`kibana import-rules/export-rules`, TOML rules, Python 3.12+) and the Kibana saved-objects NDJSON import are the other two supported "from files" paths.

## Key Question 4: What Elastic's AI/LLM features actually do (Automatic Import, AI Assistant, Attack Discovery, Automatic Migration), tiers, and accuracy evidence

### Takeaway
Elastic's **Automatic Import is exactly the "AI builds the parser" capability** — an LLM turns a sample of JSON/NDJSON/CSV/syslog into an ingest pipeline + ECS mapping packaged as a custom integration, GA, but it requires an **Enterprise** subscription (or Serverless Security Analytics Complete) plus an LLM connector, caps input at 1,000 samples/10 MB (9.4+; 100 samples on 9.0–9.3), and Elastic publishes **no accuracy numbers**; AI Assistant and Automatic Migration are likewise Enterprise-tier. The free-tier substitute for a coding agent is Elastic's own Apache-2.0 **integration-skills** repo (Beta), which drives Cursor/Claude Code/Codex to scaffold integration packages with `elastic-package`.

### Cited Findings
- Automatic Import definition: "uses a large language model (LLM) with specialized instructions to analyze source data and generate a custom integration"; listed as Generally available for Serverless and Elastic Stack — [Security overview page](https://www.elastic.co/docs/solutions/security/get-started/automatic-import)
- Requirements: "a working LLM connector"; Elastic Stack users need "An Enterprise subscription"; Serverless Security needs the Security Analytics Complete feature tier — [Automatic Import guide](https://www.elastic.co/docs/explore-analyze/ai-features/automatic-import)
- Formats: JSON/NDJSON (one event per object, shallow nesting), CSV (header row, else LLM infers names), Syslog (structured or unstructured); "The more the sample varies, the more accurate the pipeline is." — [same](https://www.elastic.co/docs/explore-analyze/ai-features/automatic-import)
- Limits: Stack 9.4+/Serverless "Maximum of 1,000 samples", samples over 100,000 characters skipped, "Maximum request size of 10 MB", "Automatic Import stops at 1,000 samples or 10 MB, whichever comes first"; Stack 9.0–9.3: only the first 100 samples are sent to the LLM — [same](https://www.elastic.co/docs/explore-analyze/ai-features/automatic-import)
- Workflow: upload sample (or pick an index with `event.original`) → choose collection method → "Analyze logs" (LLM builds ingest pipeline and ECS mappings) → "Review & approve" (edit pipeline optional) → integration installed → add to an agent policy — [same](https://www.elastic.co/docs/explore-analyze/ai-features/automatic-import)
- Caveats: performance "varies by model"; third-party models are operated by their providers and submitted data "can be used to train the models or for other purposes"; "CEL generation in Automatic Import is in beta" (9.0–9.3 docs); recommended to check mappings against ECS and use the Data Quality dashboard; no accuracy figure is given — [same](https://www.elastic.co/docs/explore-analyze/ai-features/automatic-import)
- History: documented as technical preview in 8.15 — [8.15 docs](https://www.elastic.co/guide/en/security/8.15/automatic-import.html); Elastic's launch blog says it "iteratively builds, tests, and tweaks a custom ingest pipeline until it meets Elastic integration requirements" — [Elastic blog](https://www.elastic.co/blog/automatic-import-ai-data-integration-builder)
- Independent accuracy evaluations: none found; results were Elastic docs/marketing only — [search result set, e.g. 8.19 docs](https://www.elastic.co/guide/en/security/8.19/automatic-import.html)
- AI Assistant (Security): Elastic Stack requires "An Enterprise subscription"; "You must create a generative AI connector before you can use AI Assistant"; "Elastic Managed LLMs are available out-of-the box" but "incurs additional costs"; capabilities include "Generate ES|QL queries", alert summarization quick prompt, "help create or correct rule queries", alert prioritisation; GA; "Its capabilities are still developing" and output should be cross-verified; from 9.4 Elastic Agent Builder is the default chat experience — [AI Assistant docs](https://www.elastic.co/docs/solutions/security/ai/ai-assistant)
- Attack Discovery: "Each discovery groups related alerts into an attack narrative" with MITRE mapping, users/hosts, possible threat actor; "requires at least one configured LLM connector"; GA on Stack and Serverless; can run manually, scheduled, via workflow, or from Agent Builder — [Attack Discovery docs](https://www.elastic.co/docs/solutions/security/ai/attack-discovery); 8.19 docs: "By default, Attack Discovery analyzes up to 100 alerts from the last 24 hours" and "sending more alerts than your chosen LLM can handle may result in an error" — [8.19 docs](https://www.elastic.co/guide/en/security/8.19/attack-discovery.html)
- Automatic Migration: translates SIEM rules from Microsoft Sentinel, Splunk, and QRadar "into Elastic Security rules and dashboards that you can review and edit"; Stack needs "an Enterprise subscription and machine learning enabled"; Serverless needs Security Complete; LLM connector required; Splunk rules GA since 9.1, Splunk Dashboard Studio dashboards and QRadar rules GA since 9.4, Sentinel rules preview since 9.5; QRadar dashboards not supported; detects macros, lookups, reference sets, watchlists and prompts for upload, else "partially translated"; Elastic Cloud guidance 4 GB RAM per ML zone — [Automatic Migration docs](https://www.elastic.co/docs/solutions/security/get-started/automatic-migration)
- Coding-agent route (free tier): elastic/integration-skills — "Agent workflows for building and maintaining Elastic integrations — works with Cursor, Claude Code, Codex, and any LLM-powered coding environment"; "Beta — This is the initial release"; skills `/research-integration` and `/create-integration` ("package creation, data stream scaffolding, manifest configuration, CEL programs, ingest pipelines, field mappings, and system tests"); requires Docker, `elastic-package`, `celfmt`, `stream`, `mito`, `ceplx`, `kbdash` (Go tools); Apache-2.0; 16 stars; pushed 2026-10-30 — [integration-skills README](https://github.com/elastic/integration-skills); [API](https://api.github.com/repos/elastic/integration-skills); linked from the integrations README — [integrations README](https://github.com/elastic/integrations)
- Terraform provider also exposes `kibana_agentbuilder_agent/_skill/_tool/_workflow` resources (Agent Builder as code) — [docs/resources listing](https://api.github.com/repos/elastic/terraform-provider-elasticstack/contents/docs/resources)

## Key Question 5: Sizing precedents for Elasticsearch + Kibana + Fleet + a few agents on a laptop; Elastic heap/container memory docs; Apple Silicon Docker evidence

### Takeaway
Elastic's docs say "If using Docker Desktop, make sure to allocate at least 4GB of memory", run the single-node example with `-m 1GB`, and size the JVM heap automatically from the container's memory limit; the community compose precedents run on 1.5–4 GB (docker-elk 512 MB ES heap; elastdocker 4 GB; elastic-container 512 MB heap) while SIEM distributions need 8 GB (Wazuh, HELK 5–8 GB) to 24 GB (Security Onion standalone). All official elastic/elasticsearch, elastic/kibana and elastic/elastic-agent 8.19/9.x Docker Hub tags publish **arm64** images, and Docker Desktop on Mac defaults to 50% of host RAM, so a 16 GB Apple Silicon Mac has roughly 8 GB for the stack by default.

### Cited Findings
- "If using Docker Desktop, make sure to allocate at least 4GB of memory."; example `docker run ... -m 1GB docker.elastic.co/elasticsearch/elasticsearch:9.5.6`; "Use the `-m` flag to set a memory limit for the container"; ML "require a larger container with more than 1GB of memory" (example `-m 6GB`); Kibana example has no `-m` — [Elastic docs: Docker single-node](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-elasticsearch-docker-basic)
