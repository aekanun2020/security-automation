## Key Question 1 — Detection engine: rule types, scheduling, exceptions, actions, suppression, building blocks, risk/severity, tiers, prebuilt rules, detection-rules repo, Kibana API

### Takeaway
Elastic's detection engine (custom query KQL/Lucene, EQL incl. `sequence`, threshold, indicator match, new terms, ES|QL) plus prebuilt rules, exceptions, building-block rules, rule import/export and Cases are all on the free Basic tier; what moves to paid tiers is alert suppression (Platinum+), ML anomaly rules (Platinum+), third-party notification connectors such as webhook/Slack/email (Gold+; effectively Enterprise for new buyers), editing prebuilt rules in place (Enterprise) and Attack Discovery/AI Assistant (Enterprise). The open `elastic/detection-rules` repo (Elastic License v2, ~2,300 rule TOML files) ships a Python CLI that validates rules and exports Kibana-importable NDJSON, and the Kibana Detections API covers create/import/export/bulk-enable.

### Cited Findings

**Rule types**
- The Rules UI offers seven rule types: Custom query, Event correlation (EQL), Threshold, Indicator match, New terms, ES|QL, Machine learning. — [Elastic docs: Create a detection rule](https://www.elastic.co/docs/solutions/security/detect-and-alert/create-detection-rule)
- Elastic's rule-type comparison: Custom query "matches events using KQL or Lucene"; Event correlation (EQL) "correlates events by shared fields across time... detects multi-step attack chains and gaps in expected activity"; Threshold "fires when the number of matching events, grouped by one or more fields, meets or exceeds a threshold"; New terms "fires when a value (or combination of up to three values) has never appeared in a configurable history window"; Indicator match "compares source event fields against threat intelligence indices" and enriches alerts with indicator metadata; ES|QL "uses pipe-based queries to aggregate, transform, and filter data before alerting. Each result row becomes an alert"; Machine learning "relies on machine learning anomaly detection jobs to model normal behavior and flag deviations". — [Elastic docs: About detection rules](https://www.elastic.co/docs/solutions/security/detect-and-alert/about-detection-rules)
- API rule `type` enum (from the OpenAPI operation doc): `query`, `saved_query`, `eql`, `threshold`, `threat_match`, `new_terms`, `esql`, `machine_learning`; `language` is `kuery`, `lucene`, `eql` or `esql`. Machine learning rules "require an appropriate license or a cloud deployment", the ML job must be running, and the job must include `siem` in its `groups`. — [Kibana API: Create a detection rule](https://www.elastic.co/docs/api/doc/kibana/operation/operation-createrule)

**Schedule / look-back**
- API field `interval`: "Frequency of rule execution, using a date math range... Defaults to 5m (5 minutes)." `from`/`to` are date-math bounds of the query window; `max_signals`: "Maximum number of alerts the rule can create during a single run... Defaults to `100`"; the Kibana setting `xpack.alerting.rules.run.alerts.max` is a hard ceiling (e.g. "if set to 1000, the rule can generate no more than 1000 alerts even if `max_signals` is set higher"). — [Kibana API: Create a detection rule (markdown rendering)](https://www.elastic.co/docs/api/doc/kibana/operation/operation-createrule.md)
- UI naming: "Runs every" = `interval`; "Additional look-back time" extends `from`. Elastic prebuilt "Endpoint Security" rule example: "Runs every: 5m; Searches indices from: now-10m". — [Elastic docs (8.x prebuilt rule reference)](https://www.elastic.co/guide/en/security/master/prebuilt-rule-8-3-3-endpoint-security.html)
- Elastic recommends "Additional look-back time to at least 1 minute. This ensures there are no missing alerts when a rule doesn't run exactly at its scheduled time"; duplicate alerts found during the look-back window are not created; if the Gaps column shows values, raise look-back under Edit rule settings → Schedule. — [Elastic Serverless docs: Monitor rule executions](https://elastic.co/guide/en/serverless/current/security-alerts-ui-monitor.html); [8.x: alerts-ui-monitor](https://www.elastic.co/guide/en/security/8.15/alerts-ui-monitor.html)
- "Manual rule runs" and "Rule gaps information" are on all tiers; "Automatic rule gaps fill" is Enterprise-only. — [Elastic subscriptions](https://www.elastic.co/subscriptions)

**Risk score, severity, overrides, other common fields**
- `risk_score` (integer): "A numerical representation of the alert's severity from 0 to 100, where: 0-21 represents low severity, 22-47 medium, 48-73 high, 74-100 critical." `severity` must be `low` ("of interest but generally not considered to be security incidents"), `medium` ("require investigation"), `high` ("require immediate investigation") or `critical`. `risk_score_mapping` / `severity_mapping` override alert risk/severity "with a value from the source event". `rule_name_override` sets a source field used for the alert's rule name; `timestamp_override` sets the time field queried instead of `@timestamp`; `building_block_type` "must be `default`... building-block alerts are not displayed in the UI"; `exceptions_list` is an array of exception containers "which define exceptions that prevent the rule from generating alerts even when its other criteria are met"; `threat`: "Currently, only threats described using the MITRE ATT&CK framework are supported"; `investigation_fields` are "user defined fields we use to highlight... in alert details flyout"; `throttle` "Defines how often rule actions are taken"; `index` defaults to `securitySolution:defaultIndex`; `filters` and `index` "not supported for ES|QL rules". — [Kibana API: Create a detection rule (.md)](https://www.elastic.co/docs/api/doc/kibana/operation/operation-createrule.md)

**Alert suppression**
- Supported for custom query, threshold, indicator match, event correlation (incl. sequence), new terms, ES|QL and ML rules; threshold rules use "Group by" and support only per-time-period suppression. Options: "Per rule execution" or "Per time period"; missing fields can be grouped as `null` or alerted separately (not for threshold). Field limits: "Elastic Stack 9.2 and later: up to 5 fields... 9.0 to 9.1: up to 3 fields"; ES|QL rules can suppress on fields created with `EVAL`. Suppressed count exposed as `kibana.alert.suppression.docs_count`. Suppression limits per run: custom query unlimited; threshold/EQL/ES|QL/ML = Max alerts per run (default 100); indicator match/new terms = 5x (default 500). Bulk apply/remove suppression across rules from 9.1; `securitySolution:suppressionBehaviorOnAlertClosure` advanced setting (9.2+). "Alert suppression requires an appropriate subscription." — [Elastic docs: Suppress detection alerts](https://www.elastic.co/docs/solutions/security/detect-and-alert/suppress-detection-alerts)
- Tier: "Detection alerts suppression" — Basic: no, Gold: no, Platinum: yes, Enterprise: yes. — [Elastic subscriptions](https://www.elastic.co/subscriptions)

**Building-block rules**
- Building block alerts "are hidden from the UI by default", "excluded from the Overview and Alerts pages"; show them via Additional filters → "Include building block alerts". To build a higher-order rule on hidden alerts, set the rule's Source to Index Patterns `.alerts-security.alerts-*`. Rule notifications can be added to building block rules. — [Elastic docs: About building block rules](https://www.elastic.co/docs/solutions/security/detect-and-alert/about-building-block-rules)
- The detection-rules repo keeps these in `rules_building_block/` (131 TOML files on 2026-11-02, counted from the GitHub tree API). — [github.com/elastic/detection-rules](https://github.com/elastic/detection-rules); count via `https://api.github.com/repos/elastic/detection-rules/git/trees/main?recursive=1`

**API examples (constructed from the documented fields above; not copied from docs — verify in a lab)**
```bash
# 1. Create an EQL sequence rule (KQL/EQL "correlation" ≈ QRadar event sequence rule)
curl -u elastic:$PW -H 'kbn-xsrf: true' -H 'Content-Type: application/json' \
  -X POST "$KIBANA/api/detection_engine/rules" -d '{
  "rule_id": "course-eql-psexec-then-lsass",
  "name": "Remote service install followed by LSASS access",
  "type": "eql", "language": "eql",
  "index": ["logs-endpoint.events.*","logs-windows.*"],
  "query": "sequence by host.id with maxspan=5m [process where process.name == \"PSEXESVC.exe\"] [process where process.name == \"procdump.exe\" and process.args : \"lsass*\"]",
  "interval": "5m", "from": "now-11m", "max_signals": 100,
  "risk_score": 73, "severity": "high",
  "threat": [{"framework":"MITRE ATT&CK",
     "tactic":{"id":"TA0008","name":"Lateral Movement","reference":"https://attack.mitre.org/tactics/TA0008/"},
     "technique":[{"id":"T1021","name":"Remote Services","reference":"https://attack.mitre.org/techniques/T1021/"}]}],
  "enabled": true }'

# 2. Import an NDJSON file produced by `python -m detection_rules export-rules-from-repo -o rules.ndjson`
curl -u elastic:$PW -H 'kbn-xsrf: true' \
  -X POST "$KIBANA/api/detection_engine/rules/_import?overwrite=true" \
  -F file=@rules.ndjson

# 3. Bulk-enable every rule tagged "Course"
curl -u elastic:$PW -H 'kbn-xsrf: true' -H 'Content-Type: application/json' \
  -X POST "$KIBANA/api/detection_engine/rules/_bulk_action" \
  -d '{"action":"enable","query":"alert.attributes.tags: \"Course\""}'

# 4. Close alerts (QRadar "close offense" analogue)
curl -u elastic:$PW -H 'kbn-xsrf: true' -H 'Content-Type: application/json' \
  -X POST "$KIBANA/api/detection_engine/signals/status" \
  -d '{"signal_ids":["<kibana.alert.uuid>"],"status":"closed","reason":"false_positive"}'
```
(`kbn-xsrf` is the standard Kibana header for non-GET requests; the Detections API pages fetched did not restate it, see Gaps.)

### Inferences
- **[inferred]** The free Basic tier gives a complete rule engine but a crippled *notification* path: with only Server log and Index connectors, a free deployment cannot email/Slack/webhook on alerts natively; teams would poll `.alerts-security.alerts-*` or the `signals/search` API from an external script. For a course this is the sharpest "free vs paid" line, sharper than the rule types themselves.
- **[inferred]** Because Gold/Platinum are closed to new customers, "Platinum-only" features (alert suppression, ML rules, entity risk score, host isolation, PDF reports) are in practice Enterprise or Serverless-Complete features for a new self-managed buyer.
- **[inferred]** "AI-built config" (LLM-generated rules) fits Elastic well because rules are plain JSON/TOML with a schema the `detection_rules` CLI can `validate-rule` before import, and the API supports `preview` and `dry_run` — equivalents QRadar's rule wizard does not expose as text.

## Key Question 2 — Correlation into an "offense": does Elastic have a QRadar-offense equivalent?

### Takeaway
Elastic has no single object equivalent to a QRadar offense (a magnitude-scored, auto-chained container keyed on an index field). The nearest pieces are: EQL `sequence` rules (correlate events *before* alerting), alert suppression (collapse duplicates), Alerts-page grouping (ad hoc, up to 3 fields), the Cases connector rule action (auto-create a case per grouping field within a 7-day window), Entity risk score (Platinum+; per-host/user/service 0–100 computed hourly from alert risk scores) and Attack Discovery (Enterprise; LLM groups alerts into attack narratives). QRadar's offense instead is created by the rule response, chained by "Index offense based on", scored by magnitude (relevance/severity/credibility, 0–10) and ages out dormant→inactive automatically.

### Cited Findings

**QRadar offense (IBM)**
- Offense indexing "groups events or flows from different rules" that share the indexed property; "QRadar uses the offense index parameter to determine which offenses to chain together"; e.g. "all events and flows that originate from the same IP address are added to the same offense"; rules can index "based on any piece of information" using normalized fields or a custom property ("regular expression, a calculation, or an AQL-based expression"). — [IBM docs: Offense indexing](https://www.ibm.com/docs/en/SSKMKU/com.ibm.qradar.doc/c_qradar_ug_offense_indexing.html)
- "When the indexed property value is null, an offense is not created... even when you select the Ensure the detected event is part of an offense check box"; custom properties can't index offenses created by a dispatched event; offenses indexed by normalized fields (Source IP, Destination IP) carry the event name/description as CRE payload. — [IBM docs: Offense indexing considerations](https://www.ibm.com/docs/en/SSKMKU/com.ibm.qradar.doc/c_qradar_ug_offense_indexing_considerations.html)
- Magnitude: "The magnitude rating of an offense is a measure of the importance of the offense in your environment." "Relevance determines the impact of the offense on your network." "Severity indicates the level of threat that a source poses in relation to how prepared the destination is for the attack." "Credibility indicates the integrity of the offense as determined by the credibility rating" of the log source. Inputs: number of events/flows, number of log sources, age of the offense, weight of assets, "categories, severity, relevance, and credibility of the events and flows", host vulnerabilities/threat assessment; "re-evaluated when new events are added to the offense and also at scheduled intervals". — [IBM docs: Offense prioritization (QRadar 7.5)](https://www.ibm.com/docs/en/qsip/7.5?topic=management-offense-prioritization)
- The Analyst Workflow "Magnitude graph" visualizes "how the magnitude was calculated based on relevance, credibility, and severity". — [IBM docs: Offense investigation](https://www.ibm.com/docs/en/SSKMKU/com.ibm.qradar.doc/c_analyst_wf_ui_offense_details.html)

## Key Question 3 — Query languages: KQL, Lucene, EQL, ES|QL vs QRadar AQL; Sigma backends

### Takeaway
Elastic splits querying across four languages — KQL/Lucene (filter only), EQL (event sequences, no aggregations/joins), ES|QL (SQL-like pipes with `STATS` aggregations and `LOOKUP JOIN`, GA 9.1) — all free; QRadar's single AQL is SQL-like over `events`/`flows` with `GROUP BY`, `LAST n MINUTES` time windows and reference-data functions (`REFERENCEMAP`, `REFERENCETABLE`, `REFERENCESETCONTAINS`) but no event-sequence operator. pySigma has an Elasticsearch backend (Lucene/EQL/ES|QL targets, ECS pipelines; v2.1.1, Aug 2026) and an IBM-maintained QRadar AQL backend (v0.3.2, May 2024), so one Sigma rule can be compiled for both.

### Cited Findings
- Subscription rows: "Event Query Language (EQL)" and "ES|QL (Elasticsearch Query Language)" — all tiers including Basic; "Cross-cluster ES|QL" — Enterprise only; "ES|QL Lookup Joins", "ES|QL Subqueries in FROM", "ES|QL JSON Extraction" appear as rows in the ES|QL section of the same page. — [Elastic subscriptions](https://www.elastic.co/subscriptions)
- EQL capabilities/limits (sequence, `by`, `maxspan`, `until`, `runs` 1–100, missing events, `sample`; no field-to-field comparison, no joins, no aggregation pipes in Elasticsearch EQL). — [Elastic docs: EQL syntax](https://www.elastic.co/docs/reference/query-languages/eql/eql-syntax)
- ES|QL `LOOKUP JOIN <lookup_index> ON <field_name>`: left-join semantics ("unmatched rows are kept with nulls, and multiple matches produce multiple rows"); lookup index must have `index.mode: lookup` and is always single-sharded; equality only; GA since 9.1 (preview 9.0), multi-field join GA 9.2, cross-cluster GA 9.2; example `FROM firewall_logs | LOOKUP JOIN threat_list ON source.ip`; preferred over `ENRICH` when enrichment data "changes often". — [Elastic docs: LOOKUP JOIN](https://www.elastic.co/docs/reference/query-languages/esql/esql-lookup-join)
- ES|QL detection rules: "Each result row becomes an alert"; `index`/`filters` not supported for ES|QL rules; suppression can use `EVAL`-created fields. — [About detection rules](https://www.elastic.co/docs/solutions/security/detect-and-alert/about-detection-rules); [Create rule API](https://www.elastic.co/docs/api/doc/kibana/operation/operation-createrule.md); [Suppress alerts](https://www.elastic.co/docs/solutions/security/detect-and-alert/suppress-detection-alerts)
- AQL: "a structured query language that you use to communicate with the Ariel databases" to "query and manipulate event and flow data"; tables `events`, `flows`, `simarc`; reference sets/maps/tables are queryable; subqueries usable as data source; `START`/`STOP` absolute and `LAST` relative time clauses. — [IBM docs: AQL (QRadar 7.5)](https://www.ibm.com/docs/en/qsip/7.5?topic=aql-ariel-query-language)
- AQL structure: `SELECT * FROM events` / `FROM flows`; "refine the data output of the SELECT statement by using the WHERE, GROUP BY, HAVING, ORDER BY, LIMIT, and LAST clauses", e.g. `GROUP BY logsourceid`, `ORDER BY username DESC`, `LAST 1 HOURS`. — [IBM docs: AQL query structure (7.5)](https://www.ibm.com/docs/en/SS42VS_7.5/com.ibm.qradar.doc/c_aql_introduction.html)
- AQL reference-data examples: `REFERENCETABLE('user_data','FullName',username) AS 'Full Name'`, `REFERENCEMAP('GlobalID_Mapping',username) AS 'Global ID'`, `REFERENCETABLE('ip_threat_data','Category',destinationip)`; peer-group example compares a user's bytes to `REFERENCETABLE('PeerGroupStats','average', REFERENCEMAP('PeerGroup',username))` + 3 std-dev. — [IBM docs: Reference data query examples (7.5)](https://www.ibm.com/docs/en/SS42VS_7.5/com.ibm.qradar.doc/r_aql_ref_data_examples.html)
- **[secondary]** `REFERENCESETCONTAINS('DEMO_UserName', username)` used in a `WHERE` clause. — [stahler/QRadar on GitHub](https://github.com/stahler/QRadar); [IBM Community thread](https://community.ibm.com/community/user/discussion/partial-match-in-a-reference-set?hlmlt=VT)
- pySigma Elasticsearch backend: formats `default` (Lucene), `dsl_lucene`, `eql`, `kibana_ndjson`; plus `siem_rule`/`siem_rule_ndjson` (Lucene) and `siem_rule_ndjson` for EQL and ES|QL via pipelines (`-t lucene -p lucene-kibana-siemrule.yml`, `-t eql -p eql-siemrule-ndjson.yml`, `-t esql -p esql-siemrule-ndjson.yml`); pipelines `ecs_windows`, `ecs_windows_old`, `ecs_zeek_beats`, `ecs_zeek_corelight`, `zeek_raw`, `ecs_kubernetes`, `ecs_macos_esf`; maintainers Thomas Patzke, Hendrik Bäcker ("Further maintainers required!"). — [GitHub: SigmaHQ/pySigma-backend-elasticsearch](https://github.com/SigmaHQ/pySigma-backend-elasticsearch); PyPI 2.1.1 released 2026-08-10, Python >=3.10, LGPL-3.0-only — [PyPI](https://pypi.org/project/pysigma-backend-elasticsearch/)
- pySigma QRadar AQL backend (IBM Cyber Center of Excellence, MIT): `pip install pySigma-backend-QRadar-AQL` or `sigma plugin install ibm-qradar-aql`; pipelines `qradar-aql-fields` (mapped Sigma fields only) and `qradar-aql-payload` (unmapped fields → `UTF8(payload)`; no Boolean/Null/CIDR/regex/numeric comparison on unmapped fields); example `sigma convert -t ibm-qradar-aql -p qradar-aql-payload <rule> -o <out>` → `SELECT * FROM events WHERE devicetype=12 AND LOWER("Target Process Path") LIKE '%\keepass.exe'`; requires QRadar "Properties Dictionary" content pack. — [GitHub: IBM/pySigma-backend-QRadar-AQL](https://github.com/IBM/pySigma-backend-QRadar-AQL); PyPI 0.3.2 released 2024-05-12 — [PyPI](https://pypi.org/project/pySigma-backend-QRadar-AQL/)

**Capability table [inferred from the cited docs]**

| Capability | KQL / Lucene (rule type `query`) | EQL (`eql`) | ES\|QL (`esql`) | QRadar AQL |
|---|---|---|---|---|
| Boolean filter / wildcard | yes | yes | yes (`WHERE`) | yes (`WHERE`, `LIKE`, `MATCHES`) |
| Aggregation / count-by | no (threshold rule type adds count + cardinality) | no in ES EQL | `STATS ... BY` | `GROUP BY`, `HAVING`, `COUNT` |
| Ordered multi-event sequence | no | `sequence by ... with maxspan` | no native sequence (window via `STATS` on time buckets) | no sequence operator in AQL (sequence handled by CRE rule tests, not AQL) |
| Lookup / join to reference list | via indicator-match rule type (threat index) | no | `LOOKUP JOIN` (9.1+), `ENRICH` | `REFERENCESETCONTAINS`, `REFERENCEMAP`, `REFERENCETABLE` |
| Time window in query text | no (rule `from`/`interval`) | `maxspan` within sequence | `WHERE @timestamp > NOW() - 1h` | `LAST 1 HOURS`, `START/STOP` |
| Cost tier | free | free | free (cross-cluster: Enterprise) | included in QRadar license |

### Inferences
- **[inferred]** Sigma is the practical bridge for a course that wants "same detection, two SIEMs": `sigma convert -t lucene -p ecs_windows` for Elastic and `-t ibm-qradar-aql -p qradar-aql-payload` for QRadar — but the QRadar backend's last release (May 2024) is 2+ years older than the Elasticsearch backend's (Aug 2026), so expect pySigma version pinning issues.
- **[inferred]** ES|QL + `LOOKUP JOIN` (free) now covers the "enrich events against a list" use that QRadar reference sets serve, with the caveat that the lookup index is single-shard.

### Gaps
- IBM's AQL function reference page for `REFERENCESETCONTAINS` was not found; the function is only evidenced in IBM's examples page (for `REFERENCEMAP`/`REFERENCETABLE`) and community code.
- pySigma Elasticsearch backend README does not list `ESQLBackend`/`EQLBackend` class names; only `LuceneBackend` is named.

## Key Question 6 — Alerts and response: alert index/schema, status workflow, Cases, response actions, connectors, automated response tiers

### Takeaway
Alerts live in the hidden `.alerts-security.alerts-<space-id>` index with `kibana.alert.*` fields (risk_score, severity, workflow_status open/acknowledged/closed, workflow_tags, assignees, suppression.*, rule.threat.*, building_block_type); Cases are free (user assignment Platinum+); Endpoint response actions (isolate, kill/suspend process, get-file, execute, runscript, scan) and in-rule automated responses need paid tiers (Host Isolation Platinum+, response console and third-party EDR actions Enterprise), while Osquery Manager is free on all tiers.

### Cited Findings
- Alert index: `.alerts-security.alerts-<space-id>` ("hidden system indices", mappings should not be changed). Fields: `kibana.alert.risk_score` (float), `kibana.alert.severity` (keyword; `low|medium|high|critical`), `kibana.alert.rule.name`, `kibana.alert.rule.uuid`, `kibana.alert.workflow_status`, `kibana.alert.workflow_status_updated_at`, `kibana.alert.workflow_tags` ("List of tags added to an alert"), `kibana.alert.workflow_assignee_ids`, `kibana.alert.original_time` (copied from source `@timestamp`), `kibana.alert.ancestors.*`, `kibana.alert.depth`, `kibana.alert.group.id`/`.index` (sequence grouping), `kibana.alert.threshold_result.*`, `kibana.alert.suppression.terms.field/value`, `.suppression.start/end`, `.suppression.docs_count` ("The number of suppressed alerts"), `kibana.alert.rule.threat.*`, `kibana.alert.building_block_type`, `kibana.alert.reason`, `kibana.alert.url` (needs `server.publicBaseUrl`), `kibana.alert.new_terms`. — [Elastic docs: Alert schema](https://www.elastic.co/docs/reference/security/fields-and-object-schemas/alert-schema)
- Status workflow: Open (default), Acknowledged ("under active investigation"), Closed with reasons Duplicate / False positive / True positive / Benign positive / Other or custom via `securitySolution:alertCloseReasons`; alert cleanup GA 9.4; CSV export of filtered alerts GA 9.5. — [Manage detection alerts](https://www.elastic.co/docs/solutions/security/detect-and-alert/manage-detection-alerts)
- Response actions (Elastic Defend, Agent ≥8.4): `isolate`/`release` (Host Isolation privilege), `processes`, `kill-process`, `suspend-process`, `get-file` (password-protected zip), `upload`, `execute`, `runscript` (CrowdStrike `--Raw/--CloudFile/--HostPath`, SentinelOne `--script`, Defender `--ScriptName`), `scan`, `cancel` (Defender 9.2, Elastic Defend 9.5), `memory-dump`, `status`; "Response actions and the response console UI require the appropriate subscription"; pending actions for offline hosts expire after two weeks; Response actions history needs Read privilege. — [Elastic docs: Endpoint response actions](https://www.elastic.co/docs/solutions/security/endpoint-response-actions)
- Automated response actions in rules: Isolate (warning about "unintended consequences"), Kill process, Suspend process (target by `process.pid` or custom field), Run script (GA 9.4); "Automated response actions require the appropriate subscription in Elastic Stack or project feature tier in Serverless". — [Elastic docs: Automated response actions](https://www.elastic.co/docs/solutions/security/endpoint-response-actions/automated-response-actions)
- Tier rows: "Host Isolation" Platinum/Enterprise; "Interactive response console" Enterprise; "Response actions on 3rd-party endpoint solutions" Enterprise; "Osquery Manager" all tiers; "Elastic Workflows" Enterprise; "Case management" all tiers; "Case user assignment" Platinum/Enterprise. — [Elastic subscriptions](https://www.elastic.co/subscriptions)
- Serverless: "Endpoint response actions" and "Advanced endpoint policy management" are Complete-only (Endpoint protection add-on). — [Security feature tiers](https://www.elastic.co/docs/solutions/security/security-serverless-feature-tiers)
- Alerts page actions include "Add rule or Endpoint exceptions, run Osquery, isolate hosts, and run response actions"; bulk: status, add to case, run a workflow, tags, assign, Timeline (≤2,000). — [Manage detection alerts](https://www.elastic.co/docs/solutions/security/detect-and-alert/manage-detection-alerts)

Cases connector (auto-case per rule) exists only inside rule creation. — [Elastic subscriptions](https://www.elastic.co/subscriptions); [Cases connector](https://www.elastic.co/docs/reference/kibana/connectors-kibana/cases-action-type)
- QRadar comparison: offense statuses active/dormant/inactive/closed with time-based transitions (see KQ2) — [IBM docs: Offense retention](https://www.ibm.com/docs/en/SSKMKU/com.ibm.qradar.doc/c_qradar_Off_Retention.html); offense notes and "Add note" in Analyst Workflow — [IBM docs: Offense investigation](https://www.ibm.com/docs/en/SSKMKU/com.ibm.qradar.doc/c_analyst_wf_ui_offense_details.html)

## Key Question 7 — Reporting and dashboards: Lens/dashboards, Security dashboards, CSV vs PDF/PNG tiers, scheduled reports, Reporting API vs QRadar reports

### Takeaway
Dashboards, Lens, Discover and CSV export are free; PDF/PNG reports are Gold+ (so Enterprise for new self-managed buyers), scheduled reports went GA in 9.1, and the Reporting API is `POST /api/reporting/generate/{printablePdfV2|csv}?jobParams=…` with `kbn-xsrf: true` and polling `GET /api/reporting/jobs/download/<id>` (503 until done). QRadar's Reports tab has a wizard with Manual/Hourly/Daily/Weekly/Monthly schedules, multiple output formats and e-mail distribution included.

### Cited Findings
- Report types: PDF (dashboards, visualizations, Canvas), PNG (dashboards, visualizations), CSV (saved Discover sessions), CSV download from Lens, JSON export of dashboards; "PDF reports are a subscription feature" (same for PNG); scheduled recurring reports "generally available since 9.1"; PDF/PNG unavailable on Serverless; reports stored under the `kibana-reporting` ILM policy (kept forever by default); Elastic Cloud Kibana needs ≥2 GB RAM for PDF/PNG (4 GB recommended). — [Kibana docs: Report and share](https://www.elastic.co/docs/explore-analyze/report-and-share)
- Tier rows: "CSV exports" all tiers; "PDF and PNG reports" Gold/Platinum/Enterprise (not Basic); "Lens", "Dashboards", "Discover", "ES|QL" (Data exploration) all tiers; "Drilldown to URL" Gold+; "Watcher" Gold+. — [Elastic subscriptions](https://www.elastic.co/subscriptions)
- Reporting API: copy the POST URL from the Export flyout (9.1+) / Share > Export (9.0); patterns `/api/reporting/generate/printablePdfV2?jobParams=...` and `/api/reporting/generate/csv?jobParams=...`; must be `POST` with `kbn-xsrf: true` else HTTP 400; response contains `path` like `/api/reporting/jobs/download/jxzaofkc0ykpf4062305t068`; `GET` that path returns 503 + `Retry-After` while pending, 500 on failure; Watcher can attach reports via the `reporting` attachment type (example: hourly watch, `retries: 40`, `interval: 15s`); `&sync` unsupported. — [Kibana docs: Automating report generation](https://www.elastic.co/docs/explore-analyze/report-and-share/automating-report-generation)
- Alerts page can export filtered alerts to CSV (GA 9.5). — [Manage detection alerts](https://www.elastic.co/docs/solutions/security/detect-and-alert/manage-detection-alerts)
- QRadar: "You can use the Reports tab to create, edit, distribute, and manage reports"; "Use the Report wizard to create and customize a new report"; reports without an interval must be generated manually; sharing gives another user a copy to edit/schedule; report groups. — [IBM docs: Report management](https://www.ibm.com/docs/en/SSKMKU/com.ibm.qradar.doc/c_qradar_report_mgt.html)
- QRadar Report wizard schedules: Manually ("generates 1 time"), Hourly ("end of each hour"), Daily, Weekly ("previous calendar week, from Monday to Sunday"), Monthly ("previous calendar month"); formats chosen by check boxes ("Extensible Markup Language is only available for tables"; "PDF format is smaller in size"); distribution: Report Console and/or Email ("from no_reply_reports@qradar"); generated reports "one to 2 megabytes". — [IBM docs: Creating custom reports](https://www.ibm.com/docs/en/SSKMKU/com.ibm.qradar.doc/t_qradar_crt_cust_rpt.html)

### Inferences
- **[inferred]** QRadar's scheduled e-mailed PDF report is a licensed-in capability; the free Elastic tier matches it only with live dashboards, CSV export, or an external script that renders dashboards — scheduled/emailed PDF needs Gold+ (effectively Enterprise) plus an Email connector (also Gold+).
- **[inferred]** Elastic's prebuilt Security dashboards (Overview, Detections & alerts) are part of the free Kibana Security app, since "Security information and event management (SIEM)" and "Dashboards" rows are all-tier; the specific Security dashboard pages were not fetched.

### Gaps
- `csv_searchsource`/`csv_v2`/`pngV2` export-type names and `xpack.reporting.csv.maxSizeBytes` default were not on the fetched pages.
- Tier for *scheduled* reports (beyond PDF/PNG being Gold+) was not stated.
- The Elastic Security Overview/Detections dashboard pages were not fetched this round.
