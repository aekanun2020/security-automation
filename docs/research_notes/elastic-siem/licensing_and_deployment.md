## Key Question 1 — Current 9.x version, `start-local`, and the official Docker/Compose/Agent/Fleet-Server docs (required settings)

### Takeaway
As of early Nov 2026 the current Elastic Stack line is **9.5.x** (downloads page: 9.5.5, released 6 Oct 2026; the docs' install pages already reference 9.5.6). `start-local` is a one-command, **single-node, HTTP-only, localhost-only, 30-day-trial** Elasticsearch+Kibana Compose stack with **no Fleet Server/Elastic Agent**, fully drivable non-interactively (`sh -s -- -v <ver>`, `ES_LOCAL_PASSWORD`, `ES_LOCAL_DIR`). For a SIEM lab with Fleet you must add a Fleet Server container (Elastic Agent image with `FLEET_SERVER_ENABLE=1`) and agents yourself; the official docs give every env var and API to do so without a UI.

**`start-local` — what the script actually does (read from `start-local.sh`, version `0.14.0`)**
- Elasticsearch service env: `discovery.type=single-node`, `xpack.security.enabled=true`, `xpack.security.http.ssl.enabled=false`, `xpack.license.self_generated.type=trial`, `xpack.ml.use_auto_machine_memory_percent=true`, `ES_JAVA_OPTS=${ES_LOCAL_JAVA_OPTS}`; all three disk watermarks set to `ES_LOCAL_DISK_SPACE_REQUIRED=1gb`; port published as `127.0.0.1:${ES_LOCAL_PORT}:9200`; data in named volume `dev-elasticsearch`. — [OFFICIAL] [start-local.sh](https://raw.githubusercontent.com/elastic/start-local/main/start-local.sh)
- Default heap written to `.env`: `ES_LOCAL_JAVA_OPTS="-Xms128m -Xmx2g"` (or `"-Xms2g -Xmx2g"` with `--edot`). — [OFFICIAL] [start-local.sh](https://raw.githubusercontent.com/elastic/start-local/main/start-local.sh)
- A one-shot `kibana_settings` container sets the `kibana_system` password via `POST http://elasticsearch:9200/_security/user/kibana_system/_password`; Kibana runs with `ELASTICSEARCH_HOSTS=http://elasticsearch:9200`, `ELASTICSEARCH_USERNAME=kibana_system`, `XPACK_ENCRYPTEDSAVEDOBJECTS_ENCRYPTIONKEY=${KIBANA_ENCRYPTION_KEY}`, `ELASTICSEARCH_PUBLICBASEURL=http://localhost:9200`, port `127.0.0.1:5601:5601`. — [OFFICIAL] [start-local.sh](https://raw.githubusercontent.com/elastic/start-local/main/start-local.sh)
- Trial handling: `.env` stores `ES_LOCAL_LICENSE_EXPIRE_DATE` = now + 30 days; `start.sh` prints "The one-month trial period has expired..." and then calls `POST ${ES_LOCAL_URL}/_license/start_basic?acknowledge=true` with the API key, appending `ES_LOCAL_LICENSE=basic` to `.env` on success. Trial-extension form URL printed: `https://www.elastic.co/trialextension`. — [OFFICIAL] [start-local.sh](https://raw.githubusercontent.com/elastic/start-local/main/start-local.sh)
- API key creation: `POST http://localhost:9200/_security/api_key` with `{"name":"elastic-start-local"}` as `elastic`, stored as `ES_LOCAL_API_KEY`. — [OFFICIAL] [start-local.sh](https://raw.githubusercontent.com/elastic/start-local/main/start-local.sh)
- Version selection: if `-v` is absent, queries the Elastic artifacts API for the latest GA version; on ARM64 the script appends `-arm64` to the image tag. Compose invocation is `docker compose up --wait` (or `up -d` on older Compose). — [OFFICIAL] [start-local.sh](https://raw.githubusercontent.com/elastic/start-local/main/start-local.sh)
- The script contains **no** `fleet`, `max_map_count`, or `mem_limit` strings; the only `ulimits:` block belongs to the optional EDOT service. (grep of the script.) — [OFFICIAL] [start-local.sh](https://raw.githubusercontent.com/elastic/start-local/main/start-local.sh)

**Official Docker Compose (3-node + Kibana, TLS) reference**
- Docs: "Make sure to allocate at least 4GB of memory to Docker Desktop" (Settings > Resources); `.env` variables `ELASTIC_PASSWORD`, `KIBANA_PASSWORD` (≥6 chars, alphanumeric only because the bundled bash script only handles alphanumeric input), `STACK_VERSION`, `ES_PORT` (set `127.0.0.1:9200` to restrict to host); `docker-compose up -d`; `docker-compose down -v` removes volumes; Wolfi hardened images via `-wolfi` tag suffix (Docker ≥ 20.10.10). — [OFFICIAL] [Start a multi-node cluster with Docker Compose](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-elasticsearch-docker-compose)
- The referenced `.env` file (elastic/elasticsearch repo, `main` and `9.1` branches identical): `LICENSE=basic` with comment "Set to 'basic' or 'trial' to automatically start the 30-day trial", `MEM_LIMIT=1073741824`, `CLUSTER_NAME=docker-cluster`, `KIBANA_PORT=5601`. — [OFFICIAL] [.env](https://raw.githubusercontent.com/elastic/elasticsearch/main/docs/reference/setup/install/docker/.env)
- The referenced `docker-compose.yml`: a `setup` service (runs as `user: "0"`) generates a CA and per-node certs with `bin/elasticsearch-certutil ca --silent --pem` / `cert --silent --pem`, waits for ES, then sets the `kibana_system` password via `POST https://es01:9200/_security/user/kibana_system/_password`; `es01` sets `bootstrap.memory_lock=true`, `xpack.security.http.ssl.*`, `xpack.security.transport.ssl.*`, `xpack.license.self_generated.type=${LICENSE}`, `xpack.ml.use_auto_machine_memory_percent=true`, `mem_limit: ${MEM_LIMIT}`, `ulimits: memlock: soft/hard -1`, healthcheck greps `missing authentication credentials`. — [OFFICIAL] [docker-compose.yml](https://raw.githubusercontent.com/elastic/elasticsearch/main/docs/reference/setup/install/docker/docker-compose.yml)

**Official single-node `docker run` (security auto-config)**
- `docker network create elastic`; `docker run --name es01 --net elastic -p 9200:9200 -it -m 1GB docker.elastic.co/elasticsearch/elasticsearch:9.5.6`; `-m` "sets a container memory limit, which removes the need to set the JVM size manually"; for ML/ELSER the page uses `-m 6GB` with `-e "xpack.ml.use_auto_machine_memory_percent=true"`. First start prints the `elastic` password and a Kibana enrollment token once. Reset/recreate: `docker exec -it es01 /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic`; `... /bin/elasticsearch-create-enrollment-token -s kibana`. Get CA: `docker cp es01:/usr/share/elasticsearch/config/certs/http_ca.crt .`; test `curl --cacert http_ca.crt -u elastic:$ELASTIC_PASSWORD https://localhost:9200`. Kibana: `docker run --name kib01 --net elastic -p 5601:5601 docker.elastic.co/kibana/kibana:9.5.6` then open the printed link and paste the enrollment token. — [OFFICIAL] [Install Elasticsearch with Docker](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-elasticsearch-docker-basic)
- Kibana Docker config: any setting from "Configure Kibana" can be set as an env var "written in all capitals, with underscores as word separators" (e.g. `SERVER_NAME` → `server.name`, `ELASTICSEARCH_HOSTS` → `elasticsearch.hosts`); env vars take precedence over `kibana.yml`; alternative is bind-mounting `./kibana.yml:/usr/share/kibana/config/kibana.yml` (copy the Docker defaults `server.host: "0.0.0.0"`, `elasticsearch.hosts: http://elasticsearch:9200`, etc. into it); "All information that you include in environment variables is visible through the `ps` command". — [OFFICIAL] [Install Kibana with Docker](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-kibana-with-docker)

**Production/kernel requirements for Docker (vm.max_map_count etc.)**
- "The `vm.max_map_count` kernel setting must be set to `1048576`." (Note: 9.x docs say 1048576; older 7.x/8.x docs said 262144.) Linux: `sysctl -w` + `/etc/sysctl.conf`. The page's macOS guidance is legacy (a `screen` session into the xhyve VM tty; `docker-machine ssh` for Desktop) — these mechanisms no longer exist in current Docker Desktop. — [OFFICIAL] [Production requirements and recommendations (Docker)](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-elasticsearch-docker-prod)
- Same page: Elasticsearch runs as `elasticsearch` uid:gid `1000:0`; bind mounts must be readable by it (grant group 0 or `--group-add 0`); increase `nofile`/`nproc` ulimits (example `--ulimit nofile=65535:65535`); disable swapping, or `-e "bootstrap.memory_lock=true" --ulimit memlock=-1:-1`; heap auto-sized from container memory; override only via `jvm.options.d` bind mount; `ES_JAVA_OPTS` "overrides all other JVM options" and is for testing; pin image tags; bind a volume to `/usr/share/elasticsearch/data`. — [OFFICIAL] [Production requirements (Docker)](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-elasticsearch-docker-prod)
- Docker Desktop for Mac 4.25.0 "silently lowers vm.max_map_count from 262144 to 65530, breaking Elasticsearch containers ("ExitCode": 78)"; error seen: "max virtual memory areas vm.max_map_count [65530] is too low, increase to at least [262144]"; closed 14 Nov 2023 as fixed in a subsequent Desktop release (version not named). Workarounds posted: `docker run --rm -ti --privileged centos:7 sysctl vm.max_map_count=262144` (not persistent), a privileged `fixsysctl` Compose service that the ES service `depends_on`, or `nc -U ~/Library/Containers/com.docker.docker/Data/debug-shell.sock` then `sysctl -w ...`. — [SECONDARY] [docker/for-mac#7047](https://github.com/docker/for-mac/issues/7047)

**Elastic Agent / Fleet Server in containers**
- Images: `docker.elastic.co/elastic-agent/elastic-agent` (server), `elastic-agent-slim`, `elastic-agent-complete` (needed only for browser synthetics), each with a `-wolfi` variant; 9.0+ images use Red Hat UBI minimal. "Running Elastic Agent in a container is supported only in Linux environments." Containerised agents cannot be upgraded through Fleet (replace the image). — [OFFICIAL] [Run Elastic Agent in a container](https://www.elastic.co/docs/reference/fleet/elastic-agent-container)
- Fleet Server (self-managed) minimum env: `FLEET_SERVER_ENABLE=true`, `FLEET_SERVER_ELASTICSEARCH_HOST=<es-host>`, `FLEET_SERVER_SERVICE_TOKEN=<service-token>`, `FLEET_SERVER_POLICY_ID=<fleet-server-policy>`, publish `-p 8220:8220`. Agent enrolment: `FLEET_ENROLL=1`, `FLEET_URL=<fleet-server-url>`, `FLEET_ENROLLMENT_TOKEN=<token>`. The `container` subcommand "combines enroll and run into one step". — [OFFICIAL] [Run Elastic Agent in a container](https://www.elastic.co/docs/reference/fleet/elastic-agent-container)
- State persistence: default state dir `/usr/share/elastic-agent/state`; "Without a persistent volume, the agent re-enrolls as a new agent on every start"; create a host dir, `chown 1000:1000`, mount `--volume "$(pwd)/elastic-agent-state:/state"` and set `STATE_PATH=/state` (optionally `--user 1000:1000`). Agent logs also go to stdout; Fleet Server subprocess logs are under `state/data/logs/default/*` and are **not** sent to stdout. — [OFFICIAL] [Run Elastic Agent in a container](https://www.elastic.co/docs/reference/fleet/elastic-agent-container)
- Full env-var reference (defaults): `FLEET_SERVER_ELASTICSEARCH_HOST` default `http://elasticsearch:9200`; `FLEET_SERVER_SERVICE_TOKEN` / `FLEET_SERVER_SERVICE_TOKEN_PATH`; `FLEET_SERVER_POLICY_ID`; `FLEET_SERVER_PORT`/`FLEET_SERVER_HOST` (override policy); `FLEET_SERVER_INSECURE_HTTP` default `false` ("exposes Fleet Server over insecure HTTP. Avoid unless required"); `FLEET_SERVER_ELASTICSEARCH_CA` or `FLEET_SERVER_ELASTICSEARCH_CA_TRUSTED_FINGERPRINT`; `FLEET_SERVER_CERT`/`FLEET_SERVER_CERT_KEY`; Kibana-setup vars `KIBANA_FLEET_HOST`/`KIBANA_HOST` default `http://kibana:5601`, `KIBANA_USERNAME`/`KIBANA_PASSWORD` (default `elastic`/`changeme`) "for connecting to Kibana to retrieve a service token", `KIBANA_FLEET_USERNAME`/`KIBANA_FLEET_PASSWORD`, `KIBANA_FLEET_CA`; enrolment vars `FLEET_ENROLL` (default `false`), `FLEET_URL`, `FLEET_ENROLLMENT_TOKEN`, `FLEET_TOKEN_NAME`, `FLEET_TOKEN_POLICY_NAME`, `FLEET_CA`, `FLEET_INSECURE` (default `false`), `ELASTIC_AGENT_TAGS`, `STATE_PATH`; `ELASTICSEARCH_HOST`/`ELASTICSEARCH_USERNAME`/`ELASTICSEARCH_PASSWORD`/`ELASTICSEARCH_CA`. `KIBANA_FLEET_SETUP` is **not** documented on this page. — [OFFICIAL] [Elastic Agent environment variables](https://www.elastic.co/docs/reference/fleet/agent-environment-variables)
- The one official example that bootstraps everything from a container (dev workflow doc): `docker run -e KIBANA_HOST=http://{YOUR-IP}:5601/{BASE-PATH} -e KIBANA_USERNAME=elastic -e KIBANA_PASSWORD=changeme -e ELASTICSEARCH_HOST=http://{YOUR-IP}:9200 -e ELASTICSEARCH_USERNAME=elastic -e ELASTICSEARCH_PASSWORD=changeme -e KIBANA_FLEET_SETUP=1 -e FLEET_SERVER_ENABLE=1 -e FLEET_SERVER_INSECURE_HTTP=1 -p 8220:8220 docker.elastic.co/elastic-agent/elastic-agent:{VERSION}`; Kibana needs `server.host: 0.0.0.0`; then "configure Fleet in the UI using `http://localhost:8220`". (Page is written for Kibana developers and uses an 8.0.0-SNAPSHOT placeholder.) — [OFFICIAL] [Developer workflow: Fleet UI](https://www.elastic.co/docs/extend/integrations/developer-workflow-fleet-UI)
- Fleet Server concept: "Fleet Server is a component that connects Elastic Agents to Fleet"; "Fleet Server is a subprocess that runs inside a deployed Elastic Agent"; "Fleet Server uses a service token to communicate with Elasticsearch" (service account `fleet-server`). — [OFFICIAL] [Fleet Server](https://www.elastic.co/docs/reference/fleet/fleet-server)
- On-prem Fleet Server: default agent→Fleet Server port 8220; "Quick Start" mode "generates a Fleet Server policy and enrollment token for you. It uses self-signed certificates and is not recommended for production"; "Advanced" lets you use your own policy/TLS; a CA is "not required when testing and iterating using the Quick start option". A Fleet Server is an Elastic Agent enrolled in a policy that includes the Fleet Server integration. — [OFFICIAL] [Deploy on-premises and self-managed Fleet Server](https://www.elastic.co/docs/reference/fleet/add-fleet-server-on-prem)
- Service token via Elasticsearch API: `POST /_security/service/elastic/fleet-server/credential/token/token1` (name optional; `PUT` also accepted); response `{"created":true,"token":{"name":"token1","value":"AAEAAWVsYXN0aWM..."}}`; needs cluster privilege `manage_service_account`; "Service account tokens never expire." — [OFFICIAL] [Create service account token API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-security-create-service-token)
- Service token via Kibana API: `POST /api/fleet/service_tokens` ("Create a Fleet Server service token. The token is used to enroll Fleet Server instances with Kibana"), body optional `{"remote": false}`, privilege `fleet-agents-all`, header `kbn-xsrf` required. — [OFFICIAL] [Kibana OpenAPI bundle](https://raw.githubusercontent.com/elastic/kibana/main/oas_docs/output/kibana.yaml)

### Inferences
- A SIEM lab needs more than `start-local`: the generated Compose has no Fleet Server, so Fleet-managed agents cannot enrol; Kibana's Fleet UI/API will work (Fleet is Basic) but every agent would run **standalone** unless you add a Fleet Server container. [INFERRED from the script grep + Fleet Server docs]
- Because `start-local` is HTTP-only, a Fleet Server added to it must use `FLEET_SERVER_INSECURE_HTTP=1`, agents must use `FLEET_INSECURE=1`, and the Fleet Server host entry must be `http://fleet-server:8220`; this is exactly the shape of the official dev-workflow example. [INFERRED]
- `start-local` is fully non-interactive today: `curl -fsSL https://elastic.co/start-local | sh -s -- -v 9.5.5` with `ES_LOCAL_PASSWORD`/`ES_LOCAL_DIR` exported; it uses `docker compose up --wait`, so it blocks until healthy. [INFERRED from script]
- With `discovery.type=single-node` Elasticsearch runs in a mode where the `vm.max_map_count` bootstrap check is not enforced, which is why `start-local` can omit it; a 3-node or production-mode cluster on Docker Desktop will fail unless the Desktop VM value is ≥ the enforced minimum. **Verify** on the actual Docker Desktop build (`docker run --rm alpine sysctl vm.max_map_count`). [INFERRED; the single-node/bootstrap-check interaction was not re-verified from a 9.x page this session]
- For a 36 GB Mac, a comfortable lab budget is ES container ~4–8 GB (`-m`/`mem_limit`, heap auto-sized or `-Xms2g -Xmx2g`), Kibana ~1.5–2 GB, Fleet Server agent ~0.5 GB, two or three shipping agents ~0.3–0.5 GB each — well inside Docker Desktop's "at least 4GB" minimum. [INFERRED from official memory guidance; no official per-component lab table exists]

## Key Question 2 — Subscription tiers for SIEM work; licenses (ELv2 / SSPL / AGPL); free commercial/classroom use

### Takeaway
On the self-managed subscriptions page the tiers are "Free and open - Basic", "Gold (Discontinued)", "Platinum (Existing Customers Only)", and "Enterprise". **Basic includes** SIEM, XDR, the detection engine ("correlation, indicator match, threshold"), prebuilt detection rules, Timelines, Cases, Fleet/Elastic Agent, ILM, data streams, Spaces, RBAC, API keys, CSV exports, Lens, ES|QL, and "Elastic Connectors (e.g., Server Log and Index)". **Not in Basic**: all third-party connectors (email/Slack/webhook/Jira/PagerDuty… = Gold+), Watcher (Gold+), PDF/PNG reports (Gold+), ML anomaly detection and ML-based rules (Platinum+), Entity Analytics risk score (Platinum+), alert suppression (Platinum+), SSO (Platinum+), encryption-at-rest support (Platinum+), prebuilt-rule customization and AI features (Enterprise). The free tier is under the Elastic License (ELv2) with three limitations; internal and commercial use is free.

## Key Question 3 — Kibana/Elasticsearch REST APIs for script-only provisioning

### Takeaway
Every provisioning step has a public API: Fleet (`/api/fleet/setup`, `agent_policies`, `package_policies`, `epm/packages/{name}/{version}`, `enrollment_api_keys`, `service_tokens`, `fleet_server_hosts`, `outputs`), detections (`/api/detection_engine/rules`, `_import`, `_export`, `_bulk_action`, `PUT rules/prepackaged`), timelines, exception lists, saved objects import, spaces, connectors, data views, cases, entity store. ## Key Question 4 — Sizing and ops for a one-machine lab (single node, disk/ILM, heap, snapshots, two or three agents)

### Takeaway
Official guidance: let Elasticsearch auto-size heap from the container memory limit (`-m`/`mem_limit`), keep heap ≤ 50 % of the container's memory and under ~26 GB, mount a data volume, disable swap or lock memory, set ulimits, and keep `vm.max_map_count` compliant. ILM, data streams, SLM and snapshot/restore are Basic; a shared-filesystem repo needs `path.repo` on the node. Multiple agents in containers each need their own persistent state directory or they re-enrol as new agents on every restart.

### Cited Findings
- Heap: "By default, Elasticsearch automatically sets the JVM heap size based on a node's roles and total memory"; "The minimum and maximum values must be the same"; "Set `Xms` and `Xmx` to no more than 50% of the total memory available to each Elasticsearch node"; compressed-oops: "26GB is safe on most systems and can be as large as 30GB on some systems"; for testing `ES_JAVA_OPTS="-Xms2g -Xmx2g"` ("We do not recommend using `ES_JAVA_OPTS` in production"); Docker: bind-mount options files into `/usr/share/elasticsearch/config/jvm.options.d/`; "the total memory available to Elasticsearch means the amount of memory available within the container". — [OFFICIAL] [JVM settings](https://www.elastic.co/docs/reference/elasticsearch/jvm-settings)
- Important settings: "In production, we strongly recommend you set the `path.data` and `path.logs`" outside `$ES_HOME`; failed bootstrap checks are fixed by "adjusting the server as described in Important system configuration (for example file descriptors or `vm.max_map_count`)". — [OFFICIAL] [Important Elasticsearch configuration](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/important-settings-configuration)
- Docker memory: "Make sure to allocate at least 4GB of memory to Docker Desktop"; `-m 1GB` example; `-m 6GB` + `xpack.ml.use_auto_machine_memory_percent=true` for ML. — [OFFICIAL] [Install Elasticsearch with Docker](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-elasticsearch-docker-basic)
- Entity analytics memory: risk scoring/entity store "on deployments with less than 4 GB of memory is not recommended"; "we recommend at least 8 GB of memory". — [OFFICIAL] [Turn on the risk scoring engine](https://www.elastic.co/docs/solutions/security/advanced-entity-analytics/turn-on-risk-scoring-engine)
- Transform role: "at least one node in your Elasticsearch cluster must have the transform role" (a default single node has it). — [OFFICIAL] [Elastic Security requirements](https://www.elastic.co/docs/solutions/security/get-started/elastic-security-requirements)
- Disk watermarks: start-local pins `cluster.routing.allocation.disk.watermark.low/high/flood_stage` to `1gb` so a nearly-full laptop disk does not make indices read-only. — [OFFICIAL] [start-local.sh](https://raw.githubusercontent.com/elastic/start-local/main/start-local.sh)
- ILM/data streams/SLM/snapshot APIs are Basic (see Q2 matrix). ILM tutorials exist for "Manage time series data with data streams" and "Customize built-in ILM policies in Elasticsearch". — [OFFICIAL] [Subscriptions](https://www.elastic.co/subscriptions); [ILM tutorials overview](https://www.elastic.co/docs/manage-data/lifecycle/index-lifecycle-management/tutorial-automate-rollover)
- Snapshot repo (shared FS): "first mount the file system to the same location on all master and data nodes"; add it to `path.repo` in `elasticsearch.yml` (`path: repo: - /mount/backups`); register with body `{"type":"fs","settings":{"location":"/mount/backups/my_fs_backup_location"}}`; relative paths resolve against the first `path.repo` entry; the page has no Docker-specific guidance. — [OFFICIAL] [Shared file system repository](https://www.elastic.co/docs/deploy-manage/tools/snapshot-and-restore/shared-file-system-repository)
- Agents in containers: default state at `/usr/share/elastic-agent/state`; without a volume the agent "re-enrolls as a new agent on every start"; `chown 1000:1000` the host dir, mount at `/state`, set `STATE_PATH=/state`; read-only root FS possible with a stateful mount; `tmpfs` state "can duplicate log data on restart". — [OFFICIAL] [Run Elastic Agent in a container](https://www.elastic.co/docs/reference/fleet/elastic-agent-container)
- Fleet Server scaling: "you can deploy additional Fleet Servers to manage the increased workload" (no resource table on the page). — [OFFICIAL] [Fleet Server](https://www.elastic.co/docs/reference/fleet/fleet-server)
- Fleet Server needs port 8220 reachable from agents; Elastic Defend "cannot be integrated with Elastic Agent in standalone mode" (so Fleet is mandatory for Defend demos). — [OFFICIAL] [Add Fleet Server on-prem](https://www.elastic.co/docs/reference/fleet/add-fleet-server-on-prem); [SIEM quickstart](https://www.elastic.co/docs/solutions/security/get-started/get-started-detect-with-siem)
